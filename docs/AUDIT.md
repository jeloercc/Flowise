# Secret-Leak Audit — Flowise fork (branch: zero-context-guard)

Auditor: IBM Bob (Secret Leak Auditor mode)  
Date: 2025-07-30  
Scope: credential values (`getCredentialData` / `decryptCredentialData`) and  
workspace variables (`getVars` / `prepareSandboxVars`, including `runtime` vars  
read from `process.env`).

Sinks audited:

-   **S1** LLM context (prompts, tool names/descriptions/schemas)
-   **S2** Tool output or error returned to the LLM
-   **S3** Error messages thrown into the agent loop
-   **S4** Callbacks, tracing services, structured logs or SSE traces
-   **S6** Third-party execution environment (E2B sandbox)

## Paths NOT vulnerable (disproved)

| Claim                                                      | Why it is not a finding                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `getCredentialData` return value reaching `$vars` directly | `getCredentialData` is called in `CustomTool.ts:init()` for the Pipedream path only; in the standard CustomTool path, only `getVars` (workspace variables) are placed into `$vars`. Credential objects are passed to the LangChain SDK constructors directly (e.g., `ChatOpenAI({ openAIApiKey })`) and never serialized into the sandbox. |
| NodeVM SSRF bypass via `axios`/`node-fetch`                | Both HTTP libraries are replaced with `secureAxiosWrapper`/`secureNodeFetch` via NodeVM `mock` (utils.ts:1756–1762), which call `secureAxiosRequest`/`secureFetch` with full deny-list enforcement on every redirect hop. This path is **fixed**.                                                                                          |
| `handleErrorMessage` leaking secrets into tool output      | `handleErrorMessage` is exported from `utils.ts` but is never called on the CustomTool code-execution path. It is not a sink for credential data in this flow.                                                                                                                                                                             |
| `decryptCredentialData` error leaking plaintext            | The error thrown is `'Credentials could not be decrypted.'` — a generic string with no plaintext value (utils.ts:644).                                                                                                                                                                                                                     |
| `customToolDesc` / `customToolName` containing secrets     | These fields are set by an admin at design time from the Tool DB row, not from the credential store. They do not flow through `getCredentialData`.                                                                                                                                                                                         |

## Fix suggestions (one line each)

| ID   | Fix                                                                                                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 | Strip `$vars` from the E2B variable declarations; instead inject only explicitly declared, non-sensitive bindings or use a named-binding model (Zero-Context Guard `$secureRequest`).                                     |
| F-02 | Remove `$vars` from the NodeVM sandbox object; provide a `$secureRequest(name, url, opts)` helper instead so code never sees raw values.                                                                                  |
| F-03 | Allowlist which `process.env` key names may become runtime variable values (e.g., reject keys matching `SECRET`, `KEY`, `TOKEN`, `PASSWORD`, `CRED`).                                                                     |
| F-04 | Apply regex redaction (matching `sk-…`, `ghp_…`, `Bearer …` and resolved variable values) inside `handleToolEnd` and `handleToolError` before streaming.                                                                  |
| F-05 | Apply the SSRF deny list to E2B-launched code the same way as NodeVM: inject a `$secureRequest` helper that resolves hosts server-side before passing the request to E2B, or disable outbound network in the E2B sandbox. |
| F-06 | Redact known secret patterns from exception messages before wrapping in `Sandbox Execution Error` / `NodeVM Execution Error`.                                                                                             |
| F-07 | Document that condition/prompt code must not return `$vars` values; add a lint step or output sanitizer that strips values matching known secret patterns before they enter graph state.                                  |
| F-08 | Redact tool output before logging; or gate `onToolEnd` / `onToolError` logging at `debug` level only and document the risk.                                                                                               |
| F-09 | Same as F-02 — remove `$vars` from prompt-template sandbox; require explicit, named injections.                                                                                                                           |
| F-10 | Apply the same regex redaction (per F-04) to all `run.outputs` before they are submitted to any external tracing provider.                                                                                                |
